## Main Controller Documentation (com.gsitm.pkg.co.zgspkgco0060.controller.Main)

### Overview

This document describes the public surface of the Main controller used to render and operate the financial statements tree table. It covers lifecycle, data binding, filtering, export/print, search, personalization, bookmarking, value helps, and cross‑app navigation.

- **Controller name**: `com.gsitm.pkg.co.zgspkgco0060.controller.Main`
- **Primary table**: `sap.ui.table.TreeTable` with id `T_Main`
- **Primary models**:
  - `i18n`: Resource model for texts
  - Default OData model (service with collection `/FinancialStatements`)
  - `Search`: JSONModel for search inputs (e.g., company code, options)
  - `DateRange`: JSONModel for period/year token inputs
  - `oGLAccount`: JSONModel for GL value help cache
  - `F_GLAccount_VH`: OData model for GL account value help

### Control IDs (used across the controller)

- **FilterBar**: `FB_MainSearch`
- **Table**: `T_Main`
- **Buttons**: `B_Excel`, `B_Print`
- **ComboBox**: `CB_CompanyCode`
- **MultiInputs (tokens)**:
  - `MI_PriorYear`, `MI_PriorStartMonth`, `MI_PriorEndMonth`
  - `MI_CurrentYear`, `MI_CurrentStartMonth`, `MI_CurrentEndMonth`
  - `MI_GlAccountSelected`, `MI_GlAccountTextSelected`

### Data contract (FinancialStatements)

Required properties used by the controller/binding:

- `HierarchyLevel` (number)
- `Node` or `NodeID` (string|number)
- `ParentNodeID` or `ParentNode` (string|number|null)
- `DrillState` ("expanded"|"collapsed"|"leaf")
- `NodeText` (string)
- `GlAccount` (string|null)
- `GlAccountText` (string)
- `PeriodBalance`, `ComparisonBalance`, `AbsoluteDifference`, `RelativeDifference` (number)
- `CompanyCodeCurrency` (string)

## Lifecycle

### onInit()

Sets up models, i18n, filter bar label, default tokens (year/period), initial table binding, and GL value help preload. Also prepares table personalization and tracking state.

Usage: automatically called by SAPUI5 when the view instantiates.

### onAfterRendering()

Configures table behavior (selection, visible rows, event hooks for expand/collapse, column move, rowsUpdated), initializes the Table Personalization Controller (TPC), pins the primary column, and applies group row coloring.

### onExit()

Detaches delegates/listeners and releases strong references.

---

## Top-level actions

### onSearch()

Validates required tokens, resets state, and rebinds the table with updated base filters (year/period/company). Use this after changing tokens or company code.

Example:
```javascript
// from a button press handler
this.onSearch();
```

### onExport()

Exports currently bound data and visible columns to an Excel file using `sap/ui/export/Spreadsheet`. Header labels for period columns include the date range.

### onPrint()

Opens a print window that renders the current rows and visible columns with the same screen column width proportions. Group rows are highlighted (except BS/PL and leaf rows).

### onExpandAllPress() / onCollapseAllPress()

Fully expands or collapses the tree. Busy state is managed until the table stabilizes.

### onExpandLevelUp() / onExpandLevelDown()

Incrementally expand to reveal the next level or collapse one level, keeping UI state consistent and efficient.

## Filtering

### Base table filter (server-side)

Generated by `_getTableFilter()` and applied on each bind/filter call:

- `P_SYEAR`, `P_SMONTH`, `P_SENDMONTH`
- `P_CYEAR`, `P_CMONTH`, `P_CENDMONTH`
- `P_COMPCD` (from `Search.CompanyCode`)
- Optional `P_GL0` when `Search.GL0 === true`

### Column header filter (free text)

Handled by `onColumnFilter(oEvent)`. Accepts rich syntax per column:

- Multiple values (OR): `a,b,c`
- Range (numbers): `10..100`
- Comparisons: `>10`, `<=0`
- Exact: `=ABC`
- Starts/Ends with: `^ABC`, `ABC$`
- Default: `Contains` for `GlAccountText`, `EQ` for other strings, `EQ` for numeric fields

Programmatic reset:
```javascript
this._resetColumnFilters();
```

### Custom parameters from header filter

`_onHeaderFilterToLP(oEvent)` translates specific column filters to low-level parameters and refreshes the binding without `$filter`:

- `NodeText` → `LP_NODETEXT`
- `GlAccount` → `LP_GLACCOUNT`
- `GlAccountText` → `LP_GLACCOUNTTEXT`

### Search box (inline table search)

`_buildSearchFilters(query)` creates an OR filter across `NodeText`, `GlAccount`, and `GlAccountText`. It is combined with base and column filters.

Usage:
```javascript
this._lastTableQuery = "Revenue";
this._applyTableFilters();
```

## G/L Account filters (menus)

Two dedicated menus provide multi-select filters and token mirrors:

- By account code: `onGlAccountMenuBeforeOpen`, `onGlAccountSelectionChange`, `onGlAccountMenuConfirm`, `onGlAccountMenuReset`
- By account text: `onColumnMenuBeforeOpen`, `onGlAccountTextSelectionChange`, `onColumnMenuConfirm`, `onGlAccountTextMenuReset`

Data source priority: in-memory `oGLAccount` → OData `_loadGLAll()` → fallback test data.

Confirmed selections are applied as application filters:

- `GlAccount` uses `EQ` OR
- `GlAccountText` uses `Contains` OR

Example (programmatic apply):
```javascript
// Apply GlAccount contains two codes
const oBinding = this.byId("T_Main").getBinding("rows");
oBinding.filter([
  new sap.ui.model.Filter({
    and: false,
    filters: [
      new sap.ui.model.Filter("GlAccount", sap.ui.model.FilterOperator.EQ, "12401000"),
      new sap.ui.model.Filter("GlAccount", sap.ui.model.FilterOperator.EQ, "12402000")
    ]
  })
], sap.ui.model.FilterType.Application);
```

## Search and navigation inside the table

### onTableSearch(event|string)

Expands the tree as needed, finds hits across `NodeText`, `GlAccountText`, and `GlAccount`, highlights matching rows, and scrolls to each hit cyclically.

### jumpToQuery(query, options)

Searches and jumps to the first/next match; `options.focusCol` focuses a specific column index after selection.

Example:
```javascript
await this.jumpToQuery("12401000", { focusCol: 1 });
```

## Export and Print

### _getVisibleColumnConfigFromTable()

Derives export column metadata from currently visible table columns (label, property, type). Used by export and print to mirror the UI.

### onExport()

Collects all rows (respecting hierarchy level) and exports to `.xlsx`. Period and comparison column labels include the chosen ranges.

### onPrint()

Builds printable HTML with:

- Column widths proportional to the on-screen widths
- Group row highlight for numeric columns (except BS/PL and leaf rows)
- Table headers repeated on each page

## Personalization

Table Personalization Controller (TPC) is activated on first render. State is saved to localStorage through a lightweight service and can be reset.

- `onOpenPersonalize()` opens the TPC dialog
- `onResetPersonalize()` clears stored personalization and refreshes the table layout

## Bookmarking (in-app)

Bookmarks capture and restore full app state, including:

- Search model data and period tokens
- Custom parameters and column filters
- Table personalization payload (if any)
- Column layout (order/visibility/width)
- Tree state: expanded/collapsed nodes, selected row, first visible row, expand level

APIs:

- `onBookmarkSave()` prompts for a name and persists state
- `onBookmarkManage()` opens management dialog to apply or delete bookmarks

Programmatic apply:
```javascript
// s is a previously captured state object
await this._applyAppState(s);
```

## Common task recipes

- **Run with a new period range**: set tokens via UI or programmatically with `_setSingleToken(id, value)`, then call `onSearch()`.
- **Filter by multiple GL codes**: open the code menu, select items, Confirm; or programmatically create `Filter`(EQ) OR and apply at application level.
- **Filter by multiple GL names**: open the text menu, select items, Confirm; or use comma-separated values in the column header filter for `GlAccountText` (treated as OR Contains).
- **Export/Print only visible columns**: hide/show columns via personalization; export/print will reflect visible columns and labels.
- **Bookmark current state**: click the bookmark save action; later open management, select one, and Apply to restore.

---

## Error handling and limits

- Long tree expansions are guarded with timeouts and stability checks; busy indicators are shown.
- `_loadGLAll()` pages up to 10 pages of 1000 items each by default; if the VH model is missing, it falls back to in-memory or test data.
- Filters are applied at `sap.ui.model.FilterType.Application` to avoid overriding base server filters.

---

## Notes on extensibility

- Add new numeric fields to the `NUM` set inside `_buildFilterForValueWithType` to enable range/comparison parsing.
- Update `_createColumnConfig` and `_getVisibleColumnConfigFromTable` if you add columns so export/print includes them.
- To change the group highlight targets, adjust the `WANT` set in `_applyGroupRowColors` and the `HL_COLS` set in `_buildPrintHTML`.

---

## Quick checklist for integration

- Ensure the default OData model exposes `/FinancialStatements` with the properties listed above and hierarchy annotations.
- Provide `F_GLAccount_VH` model if you want server-side GL VH paging; otherwise, feed `oGLAccount` JSON.
- Include `i18n` texts for: `title`, `PeriodBalance`, `ComparisonBalance`, `AbsoluteDifference`, `RelativeDifference`, column headers, button labels, and error/toast messages used by the controller.
